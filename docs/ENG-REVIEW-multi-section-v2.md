## 1. الحكم العام

الموجز **قابل للتنفيذ تقنياً** على Amplify Gen 2 بدون تغيير الستاك. فكرة "القسم = لبنات" تتحول مباشرة إلى سجل `Section` بأعلام (flags)، والشاشات تقرأ الأعلام. التصحيحات تحت كلها تفاصيل تنفيذ، ما فيها شي يلغي قرار Rodeo.

## 2. تصحيح جوهري واحد: الأقسام المخفية والمنشآت المعلّقة

قواعد صلاحيات Amplify **لا تفلتر الصفوف حسب قيمة حقل**. يعني:
- قسم `hidden` ومنشأة `pending` **مقروءة عبر الـ API** لأي مستخدم مسجّل، حتى لو الواجهة تخفيهم.
- هذا كان موجوداً في v1 أيضاً ("العميل يقرأ المعتمدة فقط") وما انتبهنا له.

**الحل المعتمد:** استعلامات مخصّصة للعميل (`listVisibleSections`، `listApprovedFacilities`) عبر JS resolvers تفلتر في الخادم، والنماذج الأساسية تُقرأ كاملة فقط من `ADMIN` و`FACILITY_OWNER` (لمنشآتهم). التكلفة: ~3 resolvers إضافية. ❓ موافق، أم تقبل الإخفاء بالواجهة فقط مؤقتاً (أسرع، أقل أماناً)؟

## 3. نموذج البيانات (ملخص للمخطط — التفاصيل في المرحلة 2)

### 3.1 جديد
```
Section
  slug (فريد) · nameAr* · nameEn · descAr · descEn
  icon (مفتاح من مجموعة ثابتة ~40) · colorKey (مفتاح من لوحة theme، ليس hex)
  order · status: visible | hidden
  bookingMode: appointment | subscription | both
  hasPractitioners · hasServices · hasDepartments · hasPackages · hasGallery (boolean)
  practitionerLabelAr* · practitionerLabelEn
  presetType: gym | hospital | clinic | salon | other
  → hasMany SectionCategory, Facility

SectionCategory
  sectionId · nameAr* · nameEn · order        (حد أقصى 12 لكل قسم)
```

### 3.2 معدَّل
```
Facility
  - section (enum ثابت)  →  + sectionId (علاقة)
  + categoryIds [] · + createdBy: owner | admin · + status: pending | approved | suspended
  + ownerId (مطلوب — انظر Q3)

Department   (يصير عاماً، ليس للمستشفيات فقط) · facilityId
Service · Practitioner · Package · GalleryImage   (كلها per facility، عامة)
Practitioner + departmentId (اختياري)

Booking
  + sectionId · + bookingMode · + departmentId / serviceId / practitionerId / packageId (اختيارية)
  + facilityOwnerId (للصلاحيات) · + status يضاف له cancelled_by_admin
```

### 3.3 ترحيل النوادي الحالية (بدون كسر)
1. seed يُنشئ 4 سجلات `Section` (الأنواع الجاهزة بإعدادات §2 من الموجز).
2. كل `Facility` حالية → `sectionId = gym` · `status = approved` · `createdBy = owner` · `ownerId` = مالكها الحالي.
3. نماذج الاشتراكات الحالية (خطط، عضويات، حصص) **تبقى كما هي** وتُعتبر تنفيذ `bookingMode = subscription`.
4. يُنفَّذ أولاً على الـ sandbox ويُختبر بالبيانات الحالية قبل أي إنتاج.

### 3.4 `bookingMode = both`
يحتاج منشأة فيها عضويات **و** مواعيد معاً. ممكن، لكن يضيف تعقيداً على لوحة المنشأة والحجوزات الموحّدة. **توصية:** يُدعم في المخطط من الآن (حقل enum)، ويُبنى في الواجهة **بعد** المرحلة 5. المعالج يعرضه كخيار مع شارة "قريباً". ❓

### 3.5 قواعد تعديل قسم فيه بيانات (باك إند يفرضها)
| التغيير | مسموح؟ |
|---|---|
| الاسم، الوصف، الأيقونة، اللون، الترتيب، الحالة | ✅ دائماً |
| إطفاء لبنة (L1/L2/L3/L5/L6) | ✅ — البيانات تبقى مخفية، لا تُحذف. تحذير إلزامي في الواجهة |
| تشغيل لبنة | ✅ دائماً |
| تغيير `bookingMode` | ⛔ ممنوع إذا القسم فيه أي منشأة لها حجز/اشتراك نشط |
| حذف فئة مستخدمة في خدمات | ⚠️ تُنقل الخدمات لـ "بدون فئة" |
| حذف قسم | ⛔ ممنوع إذا فيه منشأة (أي حالة). الفحص في `deleteSection` Lambda |

## 4. الصلاحيات والعمليات الإدارية

- **مجموعات Cognito:** `ADMIN`، `FACILITY_OWNER`. كل مستخدم عميل افتراضياً. (كما v1.)
- **`Section` / `SectionCategory`:** إنشاء/تعديل/حذف `ADMIN` فقط. قراءة: عبر الاستعلامات المخصّصة (§2).
- **`Facility`:** `ADMIN` كامل · `FACILITY_OWNER` حيث `ownerId = هو` · العميل عبر `listApprovedFacilities`.
- **`Booking`:** العميل حجوزاته · صاحب المنشأة حيث `facilityOwnerId = هو` · `ADMIN` قراءة + إلغاء.
- **Lambda إدارية (mutation للـ ADMIN فقط):**
  1. `adminCreateFacilityOwner(name, email, phone)` → `AdminCreateUser` + إضافة لـ `FACILITY_OWNER` + دعوة بالإيميل (كلمة مرور مؤقتة). **SMS مو متاح** حتى يخرج SNS من الـ sandbox.
  2. `adminSuspendAccount(userId)` → `AdminDisableUser` + كل منشآته `suspended`.
  3. `adminSetFacilityStatus(facilityId, status, reason)` → يرسل push/إيميل للمالك.
  4. `deleteSection(sectionId)` → يفحص عدم وجود منشآت ثم يحذف.
- **اختبار العزل** (كما v1): مالك لا يقرأ حجوزات غيره — يُضاف له: عميل لا يقرأ قسماً مخفياً ولا منشأة معلّقة.

## 5. الـ theme والألوان
- `src/theme/sectionPalette.ts`: 10 مفاتيح (`burgundy`, `navy`, `teal`, `rose`, …) لكل مفتاح `accent` و`accentSoft` و`accentInk` **مكتوبة يدوياً** (ليس اشتقاقاً حسابياً — أدق للعربي والتباين).
- `Section.colorKey` يشير للمفتاح. لا يوجد hex في البيانات. قاعدة lint v1 تبقى كما هي.
- الأيقونات: مجموعة ثابتة من `lucide-react-native` بمفاتيح نصية. **لا رفع أيقونات مخصّصة** في هذه المرحلة.
